## Lane F — Full OPA Sidecar Enforcement

Extend OPA from opt-in stub to enforced sidecar with fail-closed capability.

- Extended `ops/opa/policy.rego` with 2 new rules: `human_gate_required`, `redaction_rules` — full PolicyBundle contract now covered by Rego (6 rules total)
- Added OPA sidecar service to `ops/docker/docker-compose.yml` — boots alongside postgres, redis, api, worker
- Added `policy_opa_fail_closed: bool = False` to Settings and `OpaHttpPolicyEvaluator` — compliance/security queries rejected when OPA is unreachable and fail-closed is enabled; general queries always fall back
- Added `GET /v1/opa/health` endpoint returning `{status: "healthy"|"degraded", mode: "inline"|"opa_http"}`
- Added `health_check()` to `PolicyEvaluatorProtocol` — implemented for both inline and OPA evaluators
- 8 new tests: fail-closed True/False, regulated/general query distinction, health-check healthy/degraded

## Lane I — Full Isotonic Calibration Automation

Calibrate confidence scores against human feedback using isotonic regression.

- Implemented `compute_pava()` — pool-adjacent-violators algorithm in pure Python (no scipy dependency)
- Implemented `build_calibration_curve()` — constructs monotonically non-decreasing calibration curve from (predicted, actual) pairs
- Implemented `apply_calibration()` — maps serving_confidence through calibration curve with linear interpolation
- Added `CalibrationService.compute_curve_for_tenant()` — maps feedback labels to node confidences and builds per-tenant calibration curve
- Wired calibration into `GovernanceService.run_governance_scan()` — applied after decay, before final persist; scan summary includes `calibrated_nodes` and `calibration_curve_segments`
- 10 new tests: PAVA monotonicity, known outputs, edge cases, curve construction, interpolation, governance scan integration

## Lane J — Full Load Shedding Automation

Risk-based sampling and rate limiting for review queue at production scale.

- Rewrote `LoadSheddingService` with risk-based sampling strategy:
  - HIGH risk items: always queued
  - MEDIUM risk: queued with probability `sample_rate + (1 - sample_rate) * 0.5`
  - LOW risk: queued with probability `sample_rate`
- Added tenant-level rate tracking — when per-minute threshold exceeded, non-HIGH items face 10x throttling
- Added configurable thresholds: `load_shedding_enabled`, `load_shedding_max_items_per_minute`, `load_shedding_window_seconds`
- Backward-compatible: `enabled=False` preserves original dedup-only behavior
- 4 new tests: disabled mode, HIGH risk always queued, dedup still works, sampling rate statistical validation
